Developer Handoff

How to turn the Rootstock web app into a native iOS app with working subscriptions — and the exact contract the JavaScript already expects.

00What exists today

  • index.html — the complete app: 24 gates, spaced review, the Bar, the Drill Hall. Self-contained, offline, stores progress in localStorage. Helper scripts: drill.js, depth.js, ipa.js, pronunciations.js.
  • A full monetization layer is already wired in JS: onboarding, paywall, Settings, and gating (first 3 gates free; gates 4+, Bar, Drill require a subscription). See the RS module near the bottom of index.html.
  • Legal pages (legal/privacy.html, terms.html, support.html), the App Store listing kit, and store assets (store/icon, store/screenshots).

The JS treats the native layer as the source of truth for entitlement. Outside a native wrapper it falls back to a local simulation so the flow stays demoable in a browser. Your job: build the shell, implement StoreKit, and speak the small bridge protocol below.

01Recommended architecture

Recommendation: a thin native WKWebView shell + StoreKit 2, no server, no third-party SDK.
The app is already a polished, offline web app. Wrapping it preserves 100% of the work, ships fastest, and — because you add no analytics/ads/backend — lets you claim a genuine “Data Not Collected” privacy label, which is a real differentiator for a calm education app.
OptionEffortWhen to choose
WKWebView shell + StoreKit 2 recommendedLowShip v1 now. Full control, zero dependencies, App Store-safe (a real, functional app — not a repackaged website).
Capacitor + StoreKit pluginLow–MedIf you want a cross-platform (Android later) toolchain and plugin ecosystem. The bridge below also supports Capacitor.
Capacitor + RevenueCatMedIf you want a subscriptions dashboard, cross-platform receipts, and A/B paywalls — at the cost of adding an SDK (revisit the privacy label: typically “Purchases”/“Identifiers”).
Full native rebuild (SwiftUI)HighOnly if you outgrow the web app. Not needed for v1.

02The JavaScript ↔ native bridge contract

This is already implemented on the web side. The native shell must (a) receive messages the JS sends, and (b) call one global function to push entitlement back.

JS → native (messages the web app posts)

On WKWebView the JS posts to a message handler named rootstock; on Capacitor it posts a JSON string to window.RootstockNative.postMessage. Payloads:

// action: "status"   → app launched / needs current entitlement
// action: "purchase" → user tapped buy. { plan, productId }
// action: "restore"  → user tapped Restore Purchases
// action: "manage"   → open the system Manage Subscriptions sheet
// action: "openURL"  → open a legal/support URL. { url }
{ action: "purchase", plan: "annual", productId: "com.rootstock.full.annual" }

native → JS (push entitlement)

Call this global whenever entitlement is known or changes — on launch, after a purchase, after a restore, and on Transaction.updates. Pass either an object or a JSON string:

// Evaluate in the web view:
window.RS_setEntitlement({
  active: true,               // bool — is any Rootstock Full sub active?
  plan: "annual",           // "annual" | "monthly" | null
  trial: false,             // bool — currently in the intro free trial?
  expiresAt: 1767225600000,  // epoch ms, optional
  priceMonthly: "$4.99",     // localized price from StoreKit, optional
  priceAnnual: "$39.99"      // localized price from StoreKit, optional
});
Always feed StoreKit’s localized price strings (Product.displayPrice) into priceMonthly/priceAnnual so the paywall shows correct currency per region. Product IDs the JS uses live in PRODUCTS in index.html: com.rootstock.full.monthly and com.rootstock.full.annual. Keep them identical everywhere.

03WKWebView shell — build steps

  1. Xcode → new App (SwiftUI or UIKit), bundle id com.rootstock.app [your id], iPhone only, deployment target iOS 16+ (StoreKit 2).
  2. Add the web files (index.html + helper JS; keep legal/ in the bundle too so links work offline) to the app target as a folder reference named e.g. web/.
  3. Load it: webView.loadFileURL(bundleURL/web/index.html, allowingReadAccessTo: bundleURL/web).
  4. Register the message handler rootstock and implement userContentController(_:didReceive:) to switch on action.
  5. Configure the web view for an app feel: disable bounce/zoom, respect safe-area insets, background #f6f4ef (matches the parchment) to avoid white flashes, opaque = false only if needed.
  6. On openURL, open legal links in an in-app SFSafariViewController (or load the bundled legal/*.html).
// Handling a message from the web app
func userContentController(_ ucc: WKUserContentController, didReceive msg: WKScriptMessage) {
  guard let body = msg.body as? [String: Any],
        let action = body["action"] as? String else { return }
  switch action {
  case "status":   Task { await pushEntitlement() }
  case "purchase": Task { await buy(body["productId"] as? String) }
  case "restore":  Task { try? await AppStore.sync(); await pushEntitlement() }
  case "manage":   Task { try? await AppStore.showManageSubscriptions(in: scene) }
  case "openURL":  if let u = body["url"] as? String { open(u) }
  default: break
  }
}

04StoreKit 2 — the essentials

let ids = ["com.rootstock.full.monthly","com.rootstock.full.annual"]

// Load products (for prices)
let products = try await Product.products(for: ids)

// Buy
func buy(_ id: String?) async {
  guard let p = products.first(where: { $0.id == id }) else { return }
  if case .success(let v) = try? await p.purchase(),
     case .verified(let t) = v { await t.finish(); await pushEntitlement() }
}

// Compute entitlement from current entitlements + push to JS
func pushEntitlement() async {
  var active = false; var plan: String? = nil; var trial = false; var exp: Double? = nil
  for await result in Transaction.currentEntitlements {
    if case .verified(let t) = result, ids.contains(t.productID) {
      active = true
      plan = t.productID.contains("annual") ? "annual" : "monthly"
      if let e = t.expirationDate { exp = e.timeIntervalSince1970 * 1000 }
      // trial: inspect t.offer?.type == .introductory (StoreKit 2)
    }
  }
  let mo = products.first{ $0.id.contains("monthly") }?.displayPrice
  let yr = products.first{ $0.id.contains("annual") }?.displayPrice
  let js = "window.RS_setEntitlement(\(jsonString(active,plan,trial,exp,mo,yr)))"
  await webView.evaluateJavaScript(js)
}

// Listen for renewals/refunds for the life of the app
Task.detached { for await _ in Transaction.updates { await pushEntitlement() } }
Call pushEntitlement() on launch, after purchase, after restore, and from the Transaction.updates loop. The web app reconciles automatically — it re-renders home when entitlement arrives.

05App Store Connect setup (must match the code)

  • Create the app record; bundle id com.rootstock.app [your id].
  • Create a Subscription Group “Rootstock Full” with the two products and Product IDs from §02. Add a 3-day introductory free trial to each.
  • Fill in localized display names, review screenshot of the paywall, and prices ($4.99 / $39.99 suggested — see Listing Kit §04).
  • Generate a StoreKit configuration file in Xcode for local testing before the products are approved.
  • Test with a Sandbox Apple ID (Settings → App Store → Sandbox Account on device). Verify: buy monthly, buy annual, restore, cancel, and that gates 4+/Bar/Drill lock and unlock correctly.

06Privacy, ATT & Info.plist

  • No tracking: omit NSUserTrackingUsageDescription and the AppTrackingTransparency framework. No IDFA.
  • Bundle fonts locally (the web app currently uses Google Fonts via CDN — download and self-host the WOFF2 files, then reference them locally) so the app makes no network requests at all. This keeps “Data Not Collected” true and the app fully offline. important
  • No NSAppTransportSecurity exceptions needed once fonts are local.
  • Set UILaunchScreen to a parchment background with the centered R mark to match the in-app splash.

07Build, sign, submit

  1. Enroll in the Apple Developer Program ($99/yr) — required before you can create the app record or upload builds.
  2. In Xcode: set the team/signing (automatic is fine), version 1.0, build 1.
  3. Add the app icon set from store/icon/AppIcon-1024.png (Xcode 14+ accepts the single 1024 “single size” asset).
  4. Product → Archive → Distribute App → App Store Connect → Upload.
  5. In App Store Connect: attach the build, paste all metadata from the Listing Kit, upload the 5 screenshots, complete App Privacy (“Data Not Collected”), add the App Review notes, and submit the subscription products with the app.
  6. Submit for review. First reviews commonly take ~24–48h.
Common rejection to avoid: apps that are “just a website” get rejected under 4.2. Rootstock is a genuine, offline, native-feeling app with native StoreKit purchases and no browser chrome, which satisfies the guideline — but do make sure there’s no visible web navigation, external links open in SFSafariViewController, and the app works with no network.
